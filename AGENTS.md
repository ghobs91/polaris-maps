# AGENTS.md — Polaris Maps

## Purpose & Technology

Polaris Maps is a peer-to-peer (DePIN) maps app: turn-by-turn navigation, live traffic, POI search, transit, offline region packs, street-level imagery, and OSM editing — without a corporate cloud. Every device is a node contributing anonymous speed probes, POI data, and seeded map data over an encrypted P2P mesh.

- **App**: React Native 0.86 + Expo SDK 57 (bare workflow), TypeScript (strict), Expo Router, MapLibre, Zustand
- **P2P**: Hyperswarm (DHT peer discovery), Hypercore/Hyperdrive (file replication), Gun.js (CRDT sync), @noble/curves (secp256k1 identity + Schnorr signatures)
- **Tooling**: pnpm workspace, Jest 29, ESLint 9 (flat config), Prettier 3, husky + commitlint, Fastlane (iOS), Detox (e2e), GitHub Actions

## Commands

All commands are `pnpm` scripts from `package.json` (there is **no Makefile** — use pnpm).

```bash
pnpm install                 # install deps (postinstall patches @atproto oauth)

# Run
pnpm start                   # Metro bundler
pnpm ios                     # iOS Simulator
pnpm ios:device              # iOS device
pnpm android                 # Android Emulator

# Test
pnpm test                    # Jest unit tests
pnpm test:watch              # Jest watch mode
pnpm test:integration        # Jest integration suite
pnpm test:contract           # Jest contract suite
pnpm test:benchmark          # Performance benchmarks
pnpm test:e2e:ios            # Detox e2e (iOS simulator)
pnpm test:e2e:android        # Detox e2e (Android emulator)

# Quality
pnpm lint                    # ESLint (ts/tsx)
pnpm format                  # Prettier write
pnpm format:check            # Prettier check
pnpm typecheck               # tsc --noEmit
pnpm check                   # lint + format:check + typecheck + test

# Build / release
pnpm prebuild                # expo prebuild --clean (regenerates ios/ + android/)
pnpm ios:pods                # cd ios && bundle exec pod install
pnpm ios:beta                # Fastlane: build + upload TestFlight
pnpm ios:release             # Fastlane: build + upload for App Store release
pnpm ios:validate            # Fastlane validate lane

# CarPlay simulator
pnpm carplay:sim             # install CarPlay simulator app
pnpm carplay:resign          # resign without rebuild
pnpm carplay:doctor          # diagnose simulator setup

# P2P worklet / data
pnpm swarm:bundle            # rebuild backend/traffic-swarm.bundle.mjs with bare-pack
pnpm mapkit:token            # generate Apple MapKit JWT (needs Apple env vars)
```

iOS local build/release workflow (Fastlane lanes, signing, TestFlight): see `docs/ios-release.md` and `fastlane/Fastfile`.

## Development Workflow

1. **Inspect** — read the relevant code, its README (`src/services/*/README.md`), and tests before changing anything.
2. **Plan** — for feature work, follow the repo's spec-driven flow (`openspec/`, `.specify/`, `specs/`) when the change is substantial.
3. **Implement minimally** — small, focused changes; reuse existing patterns, naming, and folder structure.
4. **Verify** — run `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, and the most relevant tests for the changed area.
5. **Report** — summarize changes, tests run, and any assumptions or remaining risks.

## Conventions

- **Commits**: Conventional Commits via commitlint (`@commitlint/config-conventional`, husky `commit-msg` hook). Note: `subject-empty` and `type-empty` are disabled, but conventional formatting is the repo norm.
- **Pre-commit hook**: `pnpm lint && pnpm format:check` runs on every commit. Unformatted/linting code cannot be committed.
- **Formatting**: Prettier — single quotes, trailing commas `all`, print width 100, 2-space indent, semicolons.
- **TypeScript**: strict mode; path alias `@/*` → `src/*`; tests excluded from `tsconfig` include.
- **Imports**: follow existing module structure; each `src/services/*` has a README documenting its contract.
- **Zustand stores**: `map`, `traffic`, `osmPoi`, `navigation`, `transit`, `poi`, `placeList`, `peer`.
- **Env access**: `EXPO_PUBLIC_*` vars only (inlined at Metro bundle time). Non-public secrets never reach app code.
- **Do not edit generated files**: `ios/` and `android/` are generated via `expo prebuild` — edit via config plugins/`app.json`. `traffic-swarm.bundle.mjs` is a build artifact that IS intentionally committed (rebuild with `pnpm swarm:bundle`, commit the result).
- **Agent conventions**: `.github/agents/` (Copilot agents), `.github/skills/`, `.opencode/` (commands/skills), `openspec/` (spec-driven changes), `.specify/memory/constitution.md` (project constitution — read it; it defines code quality and testing standards as NON-NEGOTIABLE).

## Testing Expectations

- Per `.specify/memory/constitution.md`: every user-facing feature must have an integration test; every public function must have unit tests (happy path, error case, boundary).
- Jest suites live in `__tests__/{unit,integration,benchmark}`.
- **Known issue**: the test suite currently has pre-existing failures (Jest ESM transform config + unrelated unit failures); CI runs `pnpm test` as advisory (`continue-on-error: true`). Do not assume `pnpm test` is green; report actual results.
- Some test scripts reference config files that were not present at last audit (`jest.integration.config.js`, `jest.contract.config.js`, `jest.benchmark.config.js`, Detox `.detoxrc`) — see Known Unknowns.
- Run the most relevant tests for your change; state clearly what was run and what passed.

## Environment & Secrets

- `.env` is **gitignored** (`.env` and `.env.*`, except `.env.example`). Never commit real keys.
- Copy `.env.example` to `.env` for local development. Required public vars: `EXPO_PUBLIC_TOMTOM_API_KEY`, `EXPO_PUBLIC_HERE_API_KEY` (optional: `EXPO_PUBLIC_TOMTOM_PROXY_URL`).
- Other `EXPO_PUBLIC_*` vars used in source: `EXPO_PUBLIC_MAPKIT_PLACE_DETAIL_URL`, `EXPO_PUBLIC_MBTA_API_KEY`, `EXPO_PUBLIC_WMATA_API_KEY`, `EXPO_PUBLIC_MOBILITY_DB_API_KEY`, `EXPO_PUBLIC_MOBILITY_DB_REFRESH_TOKEN`, `EXPO_PUBLIC_OTP_BASE_URL`, `EXPO_PUBLIC_TRANSITOUS_BASE_URL`, `EXPO_PUBLIC_GEONAMES_DB_URL`, `EXPO_PUBLIC_OVERTURE_PLACES_PM_TILES_URL`, `EXPO_PUBLIC_REGION_CATALOG_URL`, `EXPO_PUBLIC_APPLE_MAPKIT_TOKEN`, `EXPO_PUBLIC_APPLE_MAPKITJS_EMBED_TOKEN`.
- Server/script-side secrets (never in app code): `APPLE_KEY_ID`, `APPLE_TEAM_ID`, `APPLE_MAPKIT_PRIVATE_KEY(_PATH)`, `APPLE_MAPKIT_TTL_DAYS` (MapKit token generation); `APP_STORE_CONNECT_KEY_ID`, `APP_STORE_CONNECT_ISSUER_ID`, `APP_STORE_CONNECT_KEY_PATH` (Fastlane); `MOBILITY_DATABASE_SERVICE_API_KEY`, `OPEN_CHARGE_MAP_API_KEY`, `VALHALLA_CONFIG_FILE`.
- CI stores these as GitHub Actions secrets (see `.github/workflows/ios-testflight.yml`).

## Safety Constraints

- Do **not** invent APIs, files, test results, environment variables, or deployment behavior. Verify against the repository.
- Do **not** modify generated files (`ios/`, `android/`, `traffic-swarm.bundle.mjs`) unless the project explicitly expects it (the bundle is committed intentionally — but rebuild rather than hand-edit).
- Do **not** access production systems or perform destructive operations (e.g. `pnpm prebuild` wipes native dirs, Fastlane uploads) without explicit user approval.
- Do **not** report tests as passing unless they were actually run.
- Do **not** add dependencies or modify lockfiles/manifests without being asked.
- Never commit secrets or `.env` files.

## Tool Usage Policy

- **Read local code first** (`src/services/*/README.md` documents each service). Use external documentation only for unfamiliar third-party APIs (MapLibre, Hyperswarm, Gun.js, Valhalla, Expo, etc.).
- Use browser/E2E tooling only for user-facing changes when available (the app is a native RN app; iOS simulator via `pnpm ios`).
- Use repository issue/CI tools only when relevant (GitHub Actions: iOS TestFlight build, weekly region-data build).
